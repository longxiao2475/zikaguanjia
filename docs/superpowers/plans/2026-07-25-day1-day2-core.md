# Day 1–2 Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将云开发 QuickStart 重置为可运行的字卡管家骨架，并完成云端用户初始化、字卡 CRUD、手动录入、首页今日计划和字卡库筛选。

**Architecture:** 云数据库是权威数据源，前端只通过 `syncSettings` 与 `cardService` 云函数读写；本地缓存只负责首屏秒开和失败降级。云函数按 `index.js → service.js → repository.js` 分层，业务规则可在 Node 环境中用内存仓储测试。

**Tech Stack:** 微信小程序原生 WXML/WXSS/JavaScript、CloudBase `wx-server-sdk`、Node.js 内置 `node:test`。

### Task 4: syncSettings.bootstrap 云函数

**Files:**
- Create: `cloudfunctions/syncSettings/index.js`
- Create: `cloudfunctions/syncSettings/service.js`
- Create: `cloudfunctions/syncSettings/repository.js`
- Create: `cloudfunctions/syncSettings/package.json`
- Create: `cloudfunctions/syncSettings/config.json`

- [ ] **Step 1: 实现纯业务 bootstrap**

根据可信 openid 查找用户；不存在时创建默认用户和默认孩子；存在但缺失默认孩子时修复关联；返回 `{user, child}`。

- [ ] **Step 2: 实现 CloudBase 仓储**

所有时间使用 `db.serverDate()`，`ownerOpenid` 来自云函数上下文，默认孩子设置为周二/四/六、20:00、提醒开启、`Asia/Shanghai`。

- [ ] **Step 3: 实现入口和错误契约**

只支持 `action=bootstrap`；成功返回 `{ok:true,data}`，校验/业务异常返回稳定错误码，不回传堆栈。
