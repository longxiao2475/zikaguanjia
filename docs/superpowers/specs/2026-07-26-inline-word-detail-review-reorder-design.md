# 字卡详情内联与复习顺序调整设计

## 背景与目标

当前字卡库和复习页虽然会在点击后更新 `showWordSheet`，但实际内容依赖 `components/word-sheet`。微信开发者工具持续报告该组件无法解析，导致拼音和组词功能在真实项目中不可用。字卡库的选择事件又只绑定在左侧圆形热区，复习状态流也没有重排当前及后续字卡的能力。

本次改动实现三个可直接验收的目标：

1. 字卡库普通模式点击整行，稳定展示该字卡的拼音、内置组词和用户补充组词。
2. 字卡库选择模式点击整行任意非编辑区域，都能选择或取消选择。
3. 复习过程中可以拖拽调整当前及后续字卡顺序，已完成结果保持不变，排序仅影响本轮。

## 已确认方案与取舍

采用页面内联详情弹层，不再使用 `word-sheet` 自定义组件。

- 方案一：继续修复组件路径或开发者工具缓存。该方案已经多次失败，无法提供稳定结果。
- 方案二：将弹层内联到字卡库和复习页。会产生少量 WXML/WXSS 重复，但彻底移除组件解析链路，风险最低。
- 方案三：新建独立详情页面。路径稳定，但点击需要页面跳转，打断复习节奏，也超出当前 MVP 的轻交互目标。

选择方案二。字典查询和输入校验仍复用 `utils/dict.js`，只让视图和页面事件各自内联，避免复制业务规则。

## 字卡详情交互

### 数据准备

页面打开详情时调用 `getWordDetail(card)`，将结果写入页面状态：

- `wordDetail.content`：字卡内容。
- `wordDetail.pinyin`：本地静态拼音表计算出的拼音；词语逐字查询并用空格拼接。
- `wordDetail.words`：内置组词与 `customWords` 去重后的列表。
- `wordDetailInput`：本次待补充的组词输入。

拼音数据继续来自 `miniprogram/utils/pinyin-data.json`，运行时不请求网络或云函数。多音字维持 MVP 当前规则，展示单字默认读音。

### 字卡库

- 普通模式下，整张 `.word-card` 绑定详情打开事件。
- “编辑”控件继续使用 `catchtap`，阻止点击冒泡到字卡详情。
- 详情使用页面内联 bottom sheet，遮罩点击关闭，面板内部阻止冒泡。
- 用户可以在详情内补充组词；保存成功后同步列表项、当前详情卡和详情内容。

### 复习页

- 点击中央大字卡打开相同结构的内联 bottom sheet。
- 补充组词成功后同步 `_reviewState.cards`、`currentCard` 和详情内容。
- 详情弹层关闭后不改变当前复习位置和已选熟练度结果。

### 空态与错误处理

- 没有拼音时不显示空拼音行。
- 没有组词时展示可理解的空态提示，并保留补充入口。
- 非法补充内容沿用 `validateCustomWord` 的提示。
- 保存失败时保留输入和弹层，使用 toast 告知原因。

## 字卡库整行选择

每张字卡根节点统一绑定 `onCardTap`：

- `selectionMode === false`：打开详情。
- `selectionMode === true`：调用现有选择切换逻辑，选择或取消当前卡。

左侧圆圈只负责显示选中状态，不再拥有独立点击职责。这样整行点击只有一个明确行为，也不会出现点击正文打开详情、点击圆圈才选择的割裂体验。一次最多选择 50 张的限制保持不变。

选择模式下不显示编辑按钮，也不打开详情。退出选择模式时清空本轮选择，维持现有行为。

## 复习顺序调整

### 入口与范围

在复习进度区域增加“调整顺序”入口。点击后打开 bottom sheet，列出当前及后续尚未标记的字卡。

- 已完成字卡属于固定前缀，不显示在拖拽列表，也不能重排。
- 当前卡包含在待排序列表的第一项。
- 少于两张待复习字卡时入口禁用或不展示，避免无意义操作。
- 排序不写云端、不修改今日计划缓存，只影响当前页面内存中的本轮复习。

### 拖拽方式

使用微信原生 `movable-area` 与纵向 `movable-view`：

- 每行提供明确的拖拽把手和序号。
- 长按或拖动行时更新纵向位置。
- 拖动结束后按目标索引调用纯函数 `reorderPendingCards(state, fromIndex, toIndex)`。
- 页面重新渲染列表位置，避免累积坐标误差。

弹层可随时关闭，关闭不会丢失已完成的重排结果。

### 状态流约束

`reorderPendingCards` 接收的索引只针对待复习后缀：

1. 保留 `cards.slice(0, results.length)` 已完成前缀。
2. 对 `cards.slice(results.length)` 进行单项移动。
3. `results` 原样保留。
4. `currentIndex` 仍等于已完成数量。
5. `currentCard` 更新为重排后待复习后缀的第一张。
6. `progressPercent` 和 `readyToSubmit` 不变。

最终提交继续只读取按真实作答顺序积累的 `results`。每次标记都使用当时的 `currentCard._id`，因此重排不会造成字卡与熟练度错配。

## 测试与验收

自动测试覆盖：

1. 页面 JSON 不再声明 `word-sheet`，WXML 不再使用 `<word-sheet>`，旧组件目录不存在。
2. 字卡库普通模式点击整行打开正确字卡详情。
3. 字卡库选择模式点击整行选择，再次点击取消，并保留 50 张上限。
4. 内联详情能够展示本地拼音和组词，并能保存用户补充组词。
5. 重排只移动未完成后缀，完成前缀和 `results` 保持不变。
6. 重排后 `currentCard` 正确，连续标记生成的最终 payload 中 cardId 与熟练度对应正确。
7. 非法或越界排序不破坏原状态。
8. 全量 Node 测试、页面 JSON 解析和 JavaScript 语法检查通过。

开发者工具验收路径：

1. 清理并重新编译后，控制台不再出现 `Component is not found`。
2. 字卡库普通模式点击字卡任意正文区域，能看到拼音和组词。
3. 进入“选择复习”，点击字卡整行可反复选择和取消。
4. 开始至少三张字卡的复习，先标记一张，再拖拽交换后两张。
5. 确认已完成卡不进入排序列表，下一张按新顺序出现，整轮提交成功。

## 非目标

- 不增加拼音搜索。
- 不实现多音字语境判定。
- 不把自定义排序永久保存到云端。
- 不改动今日计划生成算法和复习间隔算法。
