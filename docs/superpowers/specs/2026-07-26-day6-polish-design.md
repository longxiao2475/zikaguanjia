# 字卡管家 Day 6 收尾联调设计

## 目标

完成字卡库编辑/软删除、三态与主路径验收；修复搜索文字不可见、选择框被拉伸、字卡详情打不开，并让单字和词语都能在本地展示拼音。

## 根因

- `word-sheet` 四个文件在同一批次新增时，微信开发者工具增量文件索引先处理 WXML/WXSS，日志记录 `Couldn't find the module`，之后组件目录虽然完整，旧索引仍持续报告组件不存在。重建项目 fileutils 后最新日志不再出现该错误。
- 搜索输入框只设置字号，没有显式文字色、高度和光标色，在原生输入层上出现输入值与背景对比不足。
- 多选标记使用原生 `button`，其默认布局与页面通用按钮样式叠加后，固定圆形尺寸在模拟器里被拉伸。
- `dict.js` 只为单字返回拼音，词语字卡即使详情弹层打开也不显示拼音。

## 交互设计

1. 搜索框独占一行；输入值、占位文字、光标均有明确颜色，保留 300ms 防抖。
2. 列表工具行展示当前结果数和“选择复习/取消选择”。
3. 多选标记改为 `view` 热区：外层不小于 88rpx，内层视觉圆点 38rpx；正文区域始终打开详情。
4. 普通列表项右侧提供“编辑”。编辑 bottom sheet 支持修改内容和熟练度；删除入口置于编辑弹层，调用 `cardService.delete` 前二次确认。
5. `word-sheet` 对词语逐字查本地静态拼音表并以空格拼接；单字继续合并内置组词和用户自定义组词，词语仅展示用户补充的相关词。
6. 详情和编辑弹层均提供明确关闭入口，遮罩点击可退出；异步保存时按钮 loading/disabled。

## 验证范围

- Node 自动测试：词语拼音、组件路径、搜索可见样式、多选热区、编辑/删除入口、开发残留清理。
- 微信开发者工具：重新建立文件索引、无组件解析错误；模拟首页、设置、手动录入、搜索、多选临时复习、详情、编辑、复习、提醒入口。
- 真机边界：订阅授权系统弹窗、实际消息送达和麦克风权限无法由桌面自动化代替；Day 3 语音链路仍是独立未完成阶段。
